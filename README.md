# ai-config

人間が生成AIと相談して設計を決め、その設計に沿って開発するための、個人用の開発原則と初期テンプレートです。

## ファイルの役割

| ファイル | 役割 |
| --- | --- |
| `AGENTS.md` | 共通の開発原則。ルールの編集元。 |
| `CLAUDE.md` | `AGENTS.md` を指す相対シンボリックリンク。 |
| `README.md` | このリポジトリの使い方と、適用先で使う設計記録のひな形。 |
| `TASKLIST.md` | 作業計画・進捗・残課題・検証結果を管理する初期テンプレート。 |
| `.gitignore` | 環境変数ファイルやログなどの除外設定。 |
| `.gitattributes` | テキストファイルの改行をLFに統一する設定。 |

`CLAUDE.md -> AGENTS.md` のリンク先は相対パスです。ルールの本文は `AGENTS.md` だけを編集します。

## プロジェクトへの適用

1. 適用先の既存ファイルと規約を確認する。
2. `AGENTS.md` と、相対リンクの `CLAUDE.md` をプロジェクトのルートに配置する。
3. `TASKLIST.md` を配置し、目的・完了条件・作業工程・検証方法を具体化する。
4. 適用先の `README.md` に、目的、使い方、承認済みのアーキテクチャを記録する。下記のひな形を利用できる。
5. 既存ファイルがある場合は上書きせず、内容を確認して必要な項目を統合する。

新規プロジェクトにファイルをコピーする際は、シンボリックリンクを保持してください。リンクを別途作る場合は、適用先のルートで次を実行します。

```bash
test ! -e CLAUDE.md && test ! -L CLAUDE.md && ln -s AGENTS.md CLAUDE.md
```

Windows上で実体のあるシンボリックリンクを作成できない場合は、WSLのLinuxファイルシステム上で扱ってください。

## 開発の流れ

1. リポジトリ全体の構成と関連する既存実装を確認する。
2. 新規開発や重要な設計変更では、人間と生成AIが設計案を比較し、人間が最終承認する。
3. 承認された設計と承認情報を適用先の `README.md` に記録する。
4. 実装前に `TASKLIST.md` に計画・完了条件・検証方法を記載する。
5. 承認済みの設計に沿って実装し、進捗と計画変更を更新する。
6. 変更を検証し、結果・未実施事項・残課題を `TASKLIST.md` に記録する。

調査・設計検討・計画作成は承認前でも進められます。既存アーキテクチャに影響しない軽微な修正は、新たな設計承認を省略できます。作業計画と検証は引き続き必要です。

設計と承認の正本は適用先の `README.md`、タスク管理の唯一の正本は `TASKLIST.md` です。
